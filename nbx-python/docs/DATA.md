# Data

Everything is in `data/` as JSON. The dataset shipped here is **synthetic**
(50 customers, 30 offers, 260 purchases), generated by
`nbx/core/data_simulator.py`. Schemas are in `nbx/core/models.py`.

## Files

### Offer engine (NBO)

| File | One row per | Main fields |
|---|---|---|
| `customers.json` | customer | `msisdn`, `tenure_days`, `arpu`, `dv_segment`, `revenue_segment`, `rfm_score`, `usage_type`, `data_usage_tier`, `activity_level`, `is_intl_caller`, `is_roamer`, `days_since_last_purchase`, `avg_offer_price`, … |
| `offers.json` | offer | `program_rule` (code), `offer_name`, `category`, `offer_type`, `price_omr`, `data_gb`, `voice_mins`, `validity_days`, `is_data`/`is_voice`/`is_intl`/`is_roaming`, `discount_pct`, `description` |
| `purchases.json` | transaction | `transaction_id`, `msisdn`, `purchase_date`, `offer_name`, `program_rule`, `category`, `price_omr`, `purchase_count` |
| `segments.json` | segment | `segment`, `typical_behavior` |
| `revenue_history.json` | customer | `rev_m1..m3`, `rev_w1..w4`, monthly/weekly averages (data and voice) |

### Action engine (NBA)

| File | Main fields |
|---|---|
| `nba_scores_churn.json` | `msisdn`, `proba_churn`, `proba_churn_1d` |
| `nba_scores_reactivation.json` | reactivation probabilities (15 / 30 days) |
| `nba_scores_appetency.json` | data and voice appetency probabilities |
| `nba_scores_fragility.json` | data and voice fragility probabilities |
| `nba_scores_revenue_decrease.json` | revenue-decrease probability |
| `nba_activity_usage.json` | weekly (`_w1..w4`) and monthly (`_m1..m3`) voice minutes, data MB, calls, subscription, pay-as-you-go |
| `nba_targeting.json` | `nationality_group`, `nba_segment`, `excluded`, `action`, `reward`, `cost`, `propensity` (bandit training log) |

### Competitors

| File | Content |
|---|---|
| `competitors/competitor_offers.json` | 68 Omantel / Vodafone Oman plans, normalized to OMR / GB / days, each with `source_url` and `scraped_at` |
| `competitors/competitor_passages.json` | 45 text passages from the same public pages |

The prices are a **dated snapshot**. Refresh them with
`python -m nbx.scripts.scrape_competitors` (internet; robots.txt is respected, and
there is one request every 1.5 s).

### Generated (not in version control)

`python run.py setup` creates these. Delete them at any time and rebuild:
`chroma/`, `faiss_index/`, `qdrant_local/`, `lancedb/`, `milvus_lite.db`.

## Changing the data

| You want to | Do |
|---|---|
| fresh random synthetic data | `python run.py seed` (overwrites the JSON files) |
| use your own data | the **Upload & Setup** and **Upload NBA Data** tabs, or `POST /upload` / `POST /nba/upload` |
| edit the files by hand | edit them, then run `python run.py setup` and restart the API |

Uploads are validated row by row against the schemas. Every error in all
files is reported together, and nothing is written unless every file is
valid. Writes are atomic (temp file, then replace).

Not validated today: referential integrity (e.g. a purchase's `msisdn` must
exist in `customers.json`) and business rules (price ≥ 0, unique msisdn).

**Back up `data/` before you seed or upload.** Both replace the current dataset.
