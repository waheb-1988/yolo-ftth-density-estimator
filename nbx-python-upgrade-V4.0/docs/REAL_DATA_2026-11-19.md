# Checklist: the real run of 2026-11-19

Everything to set up, folder by folder, for the first run on real data. The run date **D = 2026-11-19**. The logic of this version:

- **Training of the whole base** (about 1.2M lines). The rules validate the data and build the features, segments and actions; this runs on the CPU.
- **Scoring of Target 2 only**, in two groups:
  - **group a (T2C, 50,000 lines)**: the LLM chooses the action, then the offers;
  - **group b (T2F, 50,000 lines)**: the LLM chooses the offers only.
- **No Target 1** and **no control group**.
- The LLM agents run on the laptop GPU, with Ollama (notebook 03) or vLLM (notebook 04).
- The engine only **saves** the output; it sends nothing.

Two ways to run it. Choose **one**:

| | **A. Recommended: one weekly folder** | B. Two folders |
|---|---|---|
| Notebooks | `03_gpu_agents_step_by_step` (Ollama) or `04_vllm_agents_step_by_step` (vLLM) | `01_training_step_by_step`, then `02_scoring_step_by_step` |
| LLM agents | **yes**: every agent (1 → 9) | no: the rule fallbacks only |
| Data folder | `data/weekly/2026-11-19/` | `data/training/2026-11-19/` + `data/scoring/2026-11-19/` |
| `*_score` tables | not needed (the fresh `*_auto` history is used) | needed from the second week on |

## 1. `.env` (once, in the project folder)

Open `.env`, or create it with `copy .env.example .env`, and check these lines:

```ini
# --- targets: Target 2 only, 50k + 50k, no control ---
FSDR_TARGETS=target2
FSDR_T2_CONSTRAINT_SIZE=50000
FSDR_T2_FREE_SIZE=50000
FSDR_CONTROL_SIZE=0

# --- privacy and local only ---
FSDR_PII_SALT=<a long random secret>
FSDR_LOCAL_ONLY=true

# --- vLLM only (notebook 04) ---
VLLM_API_KEY=<a long random secret>
# VLLM_HF_MODEL=Qwen/Qwen3-8B-AWQ
# VLLM_SERVED_NAME=qwen3:8b
# VLLM_OFFLINE=1            # after the first start of the server
```

**Important:** if your `.env` came from an older `.env.example`, it may say `FSDR_T2_CONSTRAINT_SIZE=25000`, `FSDR_T2_FREE_SIZE=25000` and `FSDR_CONTROL_SIZE=20000`. Those lines override the new defaults, so change them to the values above.

Check the result:

```powershell
cd D:\production\nbx-python-upgrade-V4.0
uv run python run.py check
```

## 6. Run, and what to check

| Check | Where | Expected |
|---|---|---|
| The data is usable | step T0 (Agent 1) | `T0 DONE -- pipeline train_week0`, no blocking issue (`data/runs/2026-11-19/train/T0_load/validation_report.md`) |
| The base | T2 / T3 | about 1.2M lines, every segment non-empty |
| The lists | the list step | `lists are YOURS`, about 50,000 kept in a and 50,000 in b |
| The agents (03 / 04) | steps 6–7 | `llm_nba` / `llm_scored_offers` > 0; `0 failed` in G2 |
| Target 2 | the final step | `group audit PASS`, `target2 final READY` |
| The output | `data/output/2026-11-19/` | `target2/` and **`final/input_flytxt.csv.gz`** |

Then check `details_target2.parquet` with the business, and hand over `final/input_flytxt.csv.gz` yourself.

**Time with a 1.2M base:**
- training takes about 20–25 min (CPU);
- the rules take about 3 min;
- agents 3 + 4 on the 100k customers take about **8–14 h with Ollama** (`qwen3:8b`) or **3–6 h with vLLM** (`Qwen3-8B-AWQ`). Step G2 measures the real speed first. With `TIME_BUDGET_MIN` you choose how long they run; customers past the budget get Agent 2b's cell policy.
